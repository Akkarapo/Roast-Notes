# Spec: admin

> โมดูลที่ 8 ของ Roast & Notes — ดู [CAPABILITY-MAP.md](CAPABILITY-MAP.md) · หน้าตาตาม [DESIGN.md](DESIGN.md)
> สถานะ: **อนุมัติแล้ว (2026-10-23)** · Depends on: catalog, ordering, promotions, loyalty, community · ผู้ใช้ต่อ: sales-report (ลิงก์จาก Dashboard)

## Objective

Extra Feature **Admin Dashboard** ของโจทย์: หลังร้านสำหรับ role `admin` จัดการสินค้า/ขนาดถุง/สต็อก, โปรโมชั่น, ออเดอร์ (เปลี่ยนสถานะ), สมาชิก และรีวิว พร้อมหน้าภาพรวม

**User stories**
- ในฐานะแอดมิน ฉันเห็นภาพรวมวันนี้: ยอดขาย, ออเดอร์ที่รอยืนยัน, สินค้าใกล้หมด
- ในฐานะแอดมิน ฉันเลื่อนสถานะออเดอร์ทีละขั้นจนถึง "ได้รับแล้ว" หรือยกเลิก (คืนสต็อก) และทุกการเปลี่ยนถูกบันทึกว่าใครทำเมื่อไหร่
- ในฐานะแอดมิน ฉันเพิ่ม/แก้สินค้า ราคา สต็อกแต่ละขนาดถุง โน้ตรสชาติ และตั้งล็อตหายาก
- ในฐานะแอดมิน ฉันสร้าง/แก้/ปิดคูปองและโปร Buy X Get Y และเลือกสินค้าร่วมรายการ
- ในฐานะแอดมิน ฉันค้นหาสมาชิก ดูระดับ ยอดสะสม ออเดอร์ ปรับระดับเอง และตั้ง/ถอดสิทธิ์แอดมิน
- ในฐานะแอดมิน ฉันลบรีวิวที่ไม่เหมาะสม
- ในฐานะสมาชิก หน้าออเดอร์ของฉันมี timeline สถานะ

**นอกขอบเขต**: รายงานยอดขาย/กราฟ (`sales-report`), อัปโหลดรูปสินค้า (ใช้ภาพลายเส้นเดิม), แก้คะแนน cupping (ข้อมูล CQI อ่านอย่างเดียว), แก้ข้อความรีวิวของลูกค้า, แจ้งเตือนทางอีเมล

## Data

ตารางใหม่ 1 ตาราง — ที่เหลือใช้ตารางของโมดูลอื่น

```
orders 1 ──< order_status_changes >── 0..1 users (changed_by)
```

**order_status_changes**

| คอลัมน์ | ชนิด | หมายเหตุ |
|---|---|---|
| id | bigint PK | |
| order_id | FK → orders, cascade | index (order_id, created_at) |
| from_status | enum สถานะ NULL | NULL = ตอนสร้างออเดอร์ |
| to_status | enum สถานะ | |
| changed_by | FK → users NULL, nullOnDelete | สมาชิก (สั่ง/ยกเลิกเอง) หรือแอดมิน |
| note | varchar(255) NULL | เช่น เลขพัสดุ, เหตุผลที่ยกเลิก |
| created_at | datetime | |

บันทึกทุกจุดที่สถานะเปลี่ยน: `PlaceOrder` (NULL → pending), `CancelOrder` (สมาชิก/แอดมิน), `AdvanceOrderStatus` (แอดมิน) — ผ่าน `Order::recordStatus()` ใน transaction เดียวกับการเปลี่ยน

`orders.status` ยังเก็บสถานะปัจจุบันไว้ (query/กรองเร็ว); ตารางนี้คือประวัติ

## หน้าจอ

ทุกหน้าอยู่ใต้ `/admin` (middleware web + auth + admin มีแล้ว) · แถบเมนูย่อย: **ภาพรวม · ออเดอร์ · สินค้า · โปรโมชั่น · สมาชิก · รีวิว** · ทุกตารางแบ่งหน้า 20 แถว

### ภาพรวม `/admin`
- การ์ดตัวเลข: ยอดขายวันนี้ · ยอดขายเดือนนี้ (ออเดอร์ที่ไม่ถูกยกเลิก, ตามวันสั่ง) · ออเดอร์รอยืนยัน · สินค้าใกล้หมด (ขนาดถุงที่สต็อก ≤ 5) · สมาชิกใหม่เดือนนี้
- ออเดอร์ล่าสุด 8 รายการ · รายการขนาดถุงที่ใกล้หมด (ลิงก์ไปแก้สต็อก)
- ลิงก์ "รายงานยอดขาย" (เปิดใช้เมื่อ `sales-report` เสร็จ)

### ออเดอร์ `/admin/orders`
- แท็บตามสถานะ (พร้อมจำนวน) + ค้นหาเลขออเดอร์/ชื่อ/เบอร์
- หน้ารายละเอียด: ลูกค้า (ลิงก์ไปสมาชิก) · ที่อยู่ · รายการ · ส่วนลด · timeline
- ปุ่มเดียวสำหรับขั้นถัดไป ("ยืนยันออเดอร์" → "ส่งพัสดุแล้ว" → "อยู่ระหว่างจัดส่ง" → "ได้รับแล้ว") + ช่องหมายเหตุ · ปุ่ม "ยกเลิก" เมื่อยังเป็น pending/confirmed (คืนสต็อก, ต้องใส่เหตุผล)
- เปลี่ยนเป็น "ได้รับแล้ว" → เรียก `Order::markDelivered()` (เลื่อนระดับสมาชิก) และเปิดให้รีวิว
- กติกาใช้ `OrderStatus::canTransitionTo()` เดิม · lock แถวออเดอร์ก่อนเปลี่ยน (กันกดซ้ำ/สองแท็บ)

### สินค้า `/admin/products`
- ตาราง: ชื่อ · ประเภท · ระดับคั่ว · ราคาเริ่ม · สต็อกรวม (แดงถ้ามีขนาดที่ ≤ 5) · ขายได้ (ชิ้น) · สถานะ (ขายอยู่/ปิดขาย/ล็อตหายากถึง…) · กรองประเภท/สถานะ + ค้นหา
- ฟอร์มสร้าง/แก้: ชื่อ, ชื่อเล่น (script), slug (สร้างจากชื่อ แก้ได้), ประเภท, แหล่งปลูก (เลือกจาก origins), ฟาร์ม, สายพันธุ์, กระบวนการ, ความสูง, ระดับคั่ว, วันคั่ว, คำอธิบาย, โน้ตรสชาติ (เลือกหลายตัว จัดกลุ่มตามหมวด), ขายอยู่, ล็อตหายากถึงวันที่ (ว่าง = ไม่ใช่)
- **ขนาดถุงในหน้าเดียวกัน**: ตาราง size · น้ำหนัก · ราคา · สต็อก · SKU — แก้ได้ทุกช่อง, เพิ่มขนาดที่ยังไม่มี, ลบขนาดที่ไม่เคยถูกสั่ง · เมล็ดใช้ 100g/250g/500g, ดริปแบ็กใช้ sachet
- **ปิดขาย/ลบ**: สินค้าที่เคยถูกสั่ง → ปิดขายได้อย่างเดียว (ปุ่มลบไม่แสดง, ยิงตรงได้ 422) · ไม่เคยขาย → ลบจริงได้ (ยืนยันก่อน)
- ราคาที่แก้ไม่กระทบออเดอร์เก่า (snapshot อยู่แล้ว) แต่ตะกร้าที่ค้างอยู่ใช้ราคาใหม่

### โปรโมชั่น `/admin/promotions`
- ตาราง: ชื่อ · ชนิด · โค้ด/เงื่อนไข · ช่วงเวลา · สถานะ (ใช้ได้/ยังไม่เริ่ม/หมดอายุ/ปิด) · ใช้ไปแล้ว n ครั้ง · จำนวนสินค้าร่วมรายการ
- สร้าง: เลือกชนิดก่อน (คูปอง / ซื้อ X แถม Y) — ชนิดเปลี่ยนไม่ได้หลังสร้าง (disjoint subtype)
  - คูปอง: โค้ด (unique, ตัวใหญ่), % ลด 1–100, ยอดขั้นต่ำ, ใช้ได้ทั้งหมด, ต่อคน
  - ซื้อ X แถม Y: X ≥ 1, Y ≥ 1
  - ร่วม: ชื่อ, คำอธิบาย, เริ่ม, สิ้นสุด (ว่างได้, ต้องหลังเริ่ม), เปิดใช้
  - สินค้าร่วมรายการ: checkbox จัดกลุ่มตามประเภท/ระดับคั่ว + ปุ่มลัด "เลือกคั่วอ่อนทั้งหมด" ฯลฯ · ต้องเลือกอย่างน้อย 1
- เปิด/ปิดด้วยปุ่มเดียว · ลบได้เฉพาะโปรที่ยังไม่เคยถูกใช้ (ใช้แล้ว → ปิดแทน เพื่อให้ order_discounts ยังอ้างถึงได้)

### สมาชิก `/admin/users`
- ตาราง: ชื่อ · อีเมล · role · ระดับ · ยอดสะสม · จำนวนออเดอร์ · สมัครเมื่อ · ค้นหาชื่อ/อีเมล/เบอร์ + กรอง role/ระดับ
- รายละเอียด: ข้อมูลติดต่อ · Taste Profile · ระดับ + ยอดสะสม (การ์ดเดียวกับ Member Info) · ออเดอร์ · รีวิว · Wish List
- **ปรับระดับเอง**: เลือกระดับใหม่ + เหตุผล → บันทึก · การคำนวณอัตโนมัติยังเลื่อน "ขึ้น" ได้ตามยอดเมื่อมีออเดอร์ได้รับแล้ว (ปรับลงเองได้ แต่ถ้ายอดถึงเกณฑ์ ระบบจะเลื่อนกลับเมื่อมีการคำนวณครั้งถัดไป)
- **ตั้ง/ถอดสิทธิ์แอดมิน**: ถอดสิทธิ์ตัวเองไม่ได้ · ถอดแอดมินคนสุดท้ายไม่ได้

### รีวิว `/admin/reviews`
- ตาราง: วันที่ · สินค้า · ผู้รีวิว · ดาว · วิธีชง · ความเห็น (ย่อ) · กรองดาว/วิธีชง + ค้นหาข้อความ
- ลบได้ (ยืนยันก่อน) · ไม่มีการแก้ข้อความ

### ฝั่งสมาชิก
- หน้าออเดอร์ของสมาชิก: timeline สถานะจาก `order_status_changes` (เวลา + หมายเหตุ เช่น เลขพัสดุ; ไม่แสดงชื่อแอดมิน)

## ข้อมูลตัวอย่าง

- OrderSeeder: เพิ่มประวัติสถานะให้ออเดอร์ตัวอย่างทุกใบ ไล่ทีละขั้นตามสถานะปัจจุบัน เวลาห่างกัน 2–30 ชั่วโมง (changed_by = แอดมิน ยกเว้นขั้นแรกและการยกเลิกที่ = ลูกค้า), ส่งพัสดุมีหมายเหตุเลขพัสดุสมมติ
- ไม่มีข้อมูลตัวอย่างอื่นเพิ่ม

## Code Style

```php
// app/Actions/Admin/AdvanceOrderStatus.php
public function __invoke(Order $order, OrderStatus $to, User $admin, ?string $note = null): Order
{
    return DB::transaction(function () use ($order, $to, $admin, $note) {
        $order = Order::whereKey($order->id)->lockForUpdate()->firstOrFail();
        if (! $order->status->canTransitionTo($to)) {
            throw ValidationException::withMessages(['status' => __('This order cannot move to :status.', ['status' => $to->label()])]);
        }
        $to === OrderStatus::Delivered ? $order->markDelivered() : $order->update(['status' => $to]);
        $order->recordStatus($order->getOriginal('status'), $to, $admin, $note);
        return $order;
    });
}
```

- Controllers อยู่ `app/Http/Controllers/Admin/`, FormRequest อยู่ `app/Http/Requests/Admin/`, views อยู่ `resources/views/admin/{orders,products,promotions,users,reviews}/`
- layout: `<x-admin-layout>` = app layout + แถบเมนูย่อย
- component ใหม่: `x-admin.stat-card`, `x-admin.table`, `x-admin.status-tabs`, `x-order-timeline` (ใช้ทั้งฝั่งแอดมินและสมาชิก)

## Boundaries

- **Always:** ทุก action ตรวจ role ฝั่ง server (middleware) · เปลี่ยนสถานะ/สต็อกใน transaction + lock · บันทึกประวัติสถานะทุกครั้ง · ยืนยันก่อนลบ
- **Ask first:** ลบออเดอร์ · แก้ยอดเงินในออเดอร์ · ส่งอีเมลแจ้งลูกค้า · อัปโหลดรูป
- **Never:** ลบสินค้า/ขนาดถุงที่มีใน order_items · ลบโปรที่ถูกใช้แล้ว · ให้แอดมินถอดสิทธิ์ตัวเองจนไม่มีแอดมินเหลือ

## Success Criteria

1. member เข้า `/admin/*` ไม่ได้ (403) ทุกหน้า
2. แอดมินเลื่อนออเดอร์ pending → delivered ทีละขั้น; สมาชิกเห็น timeline; ระดับสมาชิกขึ้นเมื่อยอดถึง; ปุ่มรีวิวโผล่
3. ยกเลิกออเดอร์ confirmed แล้วสต็อกกลับ + ประวัติบันทึกเหตุผล
4. สร้างสินค้าใหม่พร้อม 3 ขนาด แล้วเห็นในหน้าร้านและซื้อได้; ปิดขายแล้วหายจากหน้าร้าน
5. สร้างคูปองใหม่แล้วใช้ในตะกร้าได้ทันที; ปิดแล้วใช้ไม่ได้
6. ปรับระดับสมาชิก/ตั้งแอดมินได้ตามกติกา; ลบรีวิวได้
7. `sail artisan test` ผ่าน, `sail pint --test` สะอาด

## Decisions (2026-10-23)

1. เก็บประวัติสถานะเป็นตาราง `order_status_changes` และแสดง timeline ให้สมาชิกด้วย
2. สินค้าที่เคยขาย → ปิดขายได้อย่างเดียว; ไม่เคยขาย → ลบจริงได้
3. จัดการสมาชิก: ดู/ค้นหา/รายละเอียด, ตั้ง/ถอดแอดมิน, ปรับระดับเอง
4. รีวิว: แอดมินดูทั้งหมดและลบได้ ไม่แก้ข้อความ
